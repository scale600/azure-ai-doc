# Security

## Secrets management

- **All secrets in Key Vault** (`kv-idp-<uniq>`): storage connection, Document
  Intelligence key, OpenAI key, SQL password, dashboard API key.
- The Function App reads them via **system-assigned Managed Identity** +
  Key Vault references (`@Microsoft.KeyVault(...)` app settings).
- No secrets in code, `.env` (gitignored), `terraform.tfvars` (gitignored), or
  `web/config.js` (gitignored, generated by CI).

## Authentication

- **Function HTTP API**: custom `x-api-key` header (Key Vault `api-key`).
  `GET /api/health` is open; all data endpoints require the key.
- **Dashboard**: served by Static Web App (HTTPS only); calls the API with the
  injected key.
- **CI/CD → Azure**: OIDC federated credentials (no long-lived secrets).

## Network & transport

- TLS 1.2 minimum everywhere (storage, SQL).
- Blob container `documents` is **private** (no anonymous access).
- Static Web App is HTTPS-only via Cloudflare proxied DNS + managed TLS.

## PII handling

- **Synthetic data only** — no real user PII.
- Masking before storage (`docs` / `PRD.md` §12):
  - `name` → first letter + `*`
  - `documentNumber` → mask leading part, keep last 4
- `RawResponseJson` stored only after redaction; raw OCR never persisted in logs.

## GitHub Actions secrets/variables

| Secret | Scope |
|---|---|
| `AZURE_CLIENT_ID` / `AZURE_TENANT_ID` / `AZURE_SUBSCRIPTION_ID` | OIDC login |
| `TF_VAR_UNIQUE_SUFFIX` | resource naming |
| `AZURE_STATIC_WEB_APPS_API_TOKEN` | SWA deploy |
| `API_KEY` | injects `web/config.js` |

## Hardening checklist (before any real data)

- [ ] Replace custom `x-api-key` with Entra ID (OAuth2) for the API.
- [ ] Restrict SQL to the Function App's Managed Identity (AAD auth) instead of
      SQL admin login/password.
- [ ] Enable Key Vault purge protection + network access restriction.
- [ ] Add a Private Endpoint if the environment requires VNet isolation.
- [ ] Review the PII masking policy for production data.
