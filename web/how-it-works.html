How the AI document pipeline works

Every uploaded document flows through a five-stage pipeline where two AI services do the heavy lifting: Azure AI Document Intelligence reads and structures the document, and Azure OpenAI reasons over it to classify, summarize, and flag risks.

The pipeline at a glance

Upload → OCR & field extraction (Document Intelligence) → AI reasoning (Azure OpenAI) → Persist (Azure SQL) → Dashboard. Two of these five stages are AI — and they are the core of the system.

1

Ingestion — Blob Storage

A document is uploaded through the drag-and-drop dashboard or the REST API. The upload handler validates it — PDF / PNG / JPEG, max 4MB, max 2 pages — then stores the raw file in a private Azure Blob Storage container. A blob-created event fires the Azure Function that runs the pipeline.

2

Azure AI Document Intelligence — OCR & field extraction

The first AI layer reads the document. It runs OCR to convert the image/PDF into machine-readable text, then applies a prebuilt model to pull out structured fields with per-field confidence scores.

  • prebuilt-idDocument — extracts identity fields (name, date of birth, document number, expiration, nationality, address).
  • prebuilt-invoice — extracts invoice fields (vendor, customer, invoice/due dates, line items, subtotal, tax, total).
  • prebuilt-read — general-purpose OCR used in the auto-detect path (2-pass: read → classify).

The model is chosen from the document-type hint selected at upload (KYC_ID → idDocument, INVOICE → invoice); otherwise the pipeline falls back to prebuilt-read and lets the next AI stage classify it.

3

Azure OpenAI — AI reasoning (the core)

This is the brain of the system. The extracted OCR text and fields are passed to gpt-4.1-mini (GlobalStandard deployment) with a carefully engineered prompt, and the model reasons over the document to produce structured intelligence.

  • Prompt engineering — a system prompt defines the role and constraints ("use only the provided OCR text and extracted fields; do not invent values"), and a structured user prompt carries the type hint, extracted fields (JSON), and raw OCR text.
  • Deterministic output — temperature = 0.2 keeps responses factual and consistent across runs.
  • Strict JSON schema — the response is validated against a Pydantic model (camelCase, extra fields rejected) before it is trusted.

The model returns:

  • classification — the detected document type.
  • summary — a natural-language summary.
  • keyFields — normalized key-value fields.
  • riskFlags — anomalies such as expired documents or mismatched amounts.
  • missingFields — required fields that were not found.
  • recommendedAction — a suggested next step for an operator.
  • confidence — a 0–1 score for the overall result.
4

Persistence — Azure SQL

Structured results are written to Azure SQL across three tables: Documents (status and metadata), ExtractionResults (OCR fields and confidence), and AIInsights (the OpenAI output). Sensitive fields are masked before storage — names to the first letter, document numbers to the last four digits.

5

Visualization — Dashboard

The Static Web App dashboard renders results in real time. While a document is processing, a live stepper shows the exact AI stage in progress (Upload → OCR → AI → Done); when complete, it shows the confidence gauge, extracted key fields, summary, and any risk or missing-field flags.
